# Фича 2 — Месячный лимит на категорию

Прочитать сперва `00-codebase-map.md` и `BUILD.md`.
Делать ПОСЛЕ фичи 1 (обе трогают `CategoryRepository.update`).

## Цель
Дать возможность задать лимит трат на категорию в месяц и наглядно показывать
прогресс «потрачено из лимита» за текущий месяц.

## Философия (важно для UX)
Лимит — это ОРИЕНТИР и мягкое предупреждение, НЕ стоп-кран.
Ничего не блокируем. Показываем прогресс-бар: обычный → жёлтый у порога (~80%) →
красный при превышении. Это влияет на удержание: наказание = люди бросают бюджет.

## Валюта
Лимит храним в БАЗОВОЙ валюте приложения (той же, в которой `StatsView` считает
через `inBase`). Так сравнение «лимит vs потрачено» корректно. Валюту лимита
сохраняем для отображения, но сравниваем в базе (`inBase`). Посмотреть, как
`StatsView`/`CurrencyService` получают базовую валюту, и переиспользовать.

## Изменения

### 1. `Models/Category.swift`
Добавить опциональное поле (nil = лимита нет):
```swift
var monthlyLimit: Decimal?
```
(Достаточно суммы в базовой валюте. Отдельное поле валюты — только если реально нужно
показать символ; тогда `var monthlyLimitCurrency: String?`, но сравнение всё равно в базе.)
SwiftData: новое опциональное поле — лёгкая миграция, дефолт nil. Проверить, что
существующий `ModelContainer`/схема не требует ручной миграции (опциональные поля обычно ок).

### 2. `Sync/DTO/SyncDTOs.swift` — `CategoryDTO`
Добавить поле, сериализовать Decimal как String (как `ExpenseDTO.amount`):
```swift
var monthlyLimit: String?      // в init: monthlyLimit = m.monthlyLimit.map { "\($0)" }
```
И при чтении DTO → модель (в `SyncService.applyCategories`) распарсить обратно
`Decimal(string:)`. НАЙТИ место, где DTO копируется в существующую/новую Category,
и добавить туда `monthlyLimit`. Иначе поле не будет синкаться.
⚠️ Это единственная фича, где `applyCategories` в `SyncService` ТРОГАЕТСЯ — аккуратно,
добавить копирование поля и в ветку обновления, и в ветку создания новой Category.

### 3. `Persistence/Repositories/CategoryRepository.swift`
Расширить `update` (и, если нужно, `add`) параметром `monthlyLimit: Decimal?`.
Ставить `category.monthlyLimit = monthlyLimit` и `updatedAt = .now`.
Обновить всех вызывающих `update`.

### 4. `Features/Categories/CategoryEditorView.swift`
Добавить секцию «Лимит на месяц»:
- Поле ввода суммы (Decimal, клавиатура `.decimalPad`), пустое = без лимита.
- Показать символ базовой валюты.
- Прокинуть в `save()` → `CategoryRepository.update(..., monthlyLimit:)`.

### 5. Отображение прогресса — `Features/Categories/CategoriesView.swift`
На строке категории, у которой есть `monthlyLimit`, показать компактный прогресс:
`потрачено / лимит` за текущий месяц + тонкий прогресс-бар.
- Посчитать траты категории за текущий месяц (границы месяца через `Calendar`),
  суммировать в базе через тот же приём `inBase`, что в `StatsView`
  (переиспользовать/вынести хелпер, не дублировать конвертацию бездумно).
- Цвет бара: <80% обычный, 80–100% жёлтый, >100% красный.
- Нужен доступ к expenses: добавить `@Query` по `Expense` в `CategoriesView`
  (по аналогии со `StatsView`), отфильтровать по scope семьи и месяцу.

## Важно
- `updatedAt = .now` при любом изменении лимита (иначе синк не подхватит).
- Не блокировать добавление трат при превышении лимита.
- Пустой ввод суммы → `monthlyLimit = nil` (лимит снят), а не 0.

## Критерии приёмки
1. `BUILD SUCCEEDED`.
2. В редакторе категории можно задать и снять лимит; сохраняется и переживает перезапуск.
3. На экране категорий у категории с лимитом виден прогресс за текущий месяц,
   цвет меняется у порога и при превышении.
4. Лимит уходит в Firestore и приходит на другое устройство семьи
   (поле есть в `CategoryDTO` и копируется в `applyCategories`).
5. Трату всё ещё можно добавить сверх лимита (не блокируем).
